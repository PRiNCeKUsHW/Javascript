::: code app/api/v1/attachments.py | Uploading a file
```python
MAX_BYTES = 5 * 1024 * 1024
ALLOWED = {"image/png", "image/jpeg", "application/pdf"}

@router.post("/tasks/{task_id}/attachments", status_code=201)
async def upload(task_id: int, file: UploadFile):
    if file.content_type not in ALLOWED:
        raise HTTPException(415, "Only PNG, JPEG or PDF")
    path = UPLOAD_DIR / f"{task_id}-{Path(file.filename).name}"
    size = 0
    with path.open("wb") as out:
        while chunk := await file.read(1024 * 1024):
            size += len(chunk)
            if size > MAX_BYTES:
                path.unlink(missing_ok=True)
                raise HTTPException(413, "File larger than 5 MB")
            out.write(chunk)
    return {"filename": path.name, "size": size}
```

@5 > Declare a parameter of type UploadFile. FastAPI reads the multipart form for you.
@6-7 > Reject anything that isn't allowed, with four fifteen, unsupported media type.
@8 > Path dot name keeps only the file name. A file called dot dot slash dot dot slash etc slash passwd can't escape our folder.
@10-16 > Then we copy it in one megabyte chunks, and stop with four thirteen as soon as it gets too big.
@all L> Why chunks? Can't I just read the whole file?

from fastapi.sse import EventSourceResponse, ServerSentEvent


@router.get("/reports/{report_id}/progress", response_class=EventSourceResponse)
async def report_progress(report_id: int):
    for percent in (0, 25, 50, 75, 100):
        yield ServerSentEvent(event="progress", data={"report": report_id, "percent": percent})
        await asyncio.sleep(1)

::: code app/api/v1/board.py | A live task board with WebSockets
```python
class Board:
    def __init__(self):
        self.sockets: list[WebSocket] = []

    async def join(self, ws: WebSocket):
        await ws.accept()
        self.sockets.append(ws)

    def leave(self, ws: WebSocket):
        self.sockets.remove(ws)

    async def broadcast(self, message: dict):
        for ws in self.sockets:
            await ws.send_json(message)


board = Board()
```
@1-3 > For a live team board, we keep a list of connected sockets.
@5-7 > When someone joins, we accept the connection and remember it.
@9-10 > When they leave, we forget it.
@12-14 > Broadcast sends a message to everyone connected.
:::

async def board_socket(ws: WebSocket, name: str):
    await board.join(ws)

        while True:

            await board.broadcast({"from": name, "text": text})

::: concept Offset vs cursor pagination
visual: database
- 🔢 **Offset**: `?page=500` → `OFFSET 4990` scans and skips rows
> Now pagination. Offset pagination, like page five hundred, makes the database read and throw away thousands of rows. It gets slower with every page.
- 🔀 New rows shift pages: items repeat or vanish
> And when new rows arrive, pages shift, so users see items twice, or miss them.
- 📍 **Cursor**: "give me 10 after id 4990" → uses the index
> A cursor says: give me ten items after id four thousand nine ninety. The database jumps straight there using the index.
- ♾️ Perfect for feeds and infinite scroll
> Cursors are perfect for feeds and infinite scroll.
:::

::: code app/api/v1/tasks.py | Cursor pagination
```python
class Page(BaseModel):
    items: list[TaskOut]
    next_cursor: int | None


@router.get("/tasks", response_model=Page)
async def list_tasks(user: CurrentUser, session: SessionDep,
                     limit: Annotated[int, Query(ge=1, le=100)] = 10, cursor: int = 0):
    stmt = (select(Task).where(Task.owner_id == user.id, Task.id > cursor)
            .order_by(Task.id).limit(limit + 1))
    rows = (await session.scalars(stmt)).all()
    has_more = len(rows) > limit
    items = rows[:limit]
    return {"items": items, "next_cursor": items[-1].id if has_more else None}
```
@1-3 > The response has the items, and a cursor for the next page.
@8 > The limit is capped at one hundred, so nobody can ask for a million rows.
@9-10 > Fetch rows with an id after the cursor, in order. Notice limit plus one.
@12-13 > That one extra row tells us if there's another page, without a second count query.
@14 > The last id becomes the next cursor, or null on the last page.
@all L> Clever. The extra row is the trick.

::: code app/core/rate_limit.py | Rate limiting with Redis
```python
def rate_limit(limit: int, window: int):
    async def check(request: Request, redis: RedisDep):
        key = f"rl:{request.client.host}:{request.url.path}"
        count = await redis.incr(key)
        if count == 1:
            await redis.expire(key, window)
        if count > limit:
            ttl = await redis.ttl(key)
            raise HTTPException(429, "Too many requests",
                                headers={"Retry-After": str(ttl)})
    return Depends(check)


@router.post("/auth/token", dependencies=[rate_limit(limit=5, window=60)])
async def login(...): ...
```
@1-2 > A dependency factory. You choose the limit and the time window.
@3 > One counter per client IP and path.
@4-6 > Redis incr adds one, atomically, even with many workers. The first request starts the timer.
@7-10 > Over the limit? Four twenty nine, too many requests, and a Retry After header.
@13-14 > Now login allows five attempts per minute. That stops password guessing.
@all L> Sixth request gets four twenty nine, and Retry After sixty. I tested it.

::: code app/api/v1/board.py | Project solution: Redis pub/sub across workers
```python
async def publish(redis: Redis, message: dict):
    await redis.publish("board", json.dumps(message))


async def relay(redis: Redis):
    pubsub = redis.pubsub()
    await pubsub.subscribe("board")
    async for msg in pubsub.listen():
        if msg["type"] == "message":
            await board.broadcast(json.loads(msg["data"]))
```
@1-2 > Here's the stretch goal. Instead of broadcasting directly, endpoints publish to a Redis channel.
@5-7 > Every worker runs a relay task, started in lifespan, that subscribes to the channel.
@8-10 > Each message is broadcast to the sockets connected to that worker. Now every user sees every update, whichever worker they're on.
@all L> So Redis is the shared loudspeaker between workers.
@all > Exactly right.
