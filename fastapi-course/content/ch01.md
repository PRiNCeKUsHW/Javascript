::: analogy An API is like a restaurant waiter
> API को समझने का सबसे आसान तरीका है एक restaurant।
- 🧑 You place an order => The client (browser, mobile app) sends a **request**
> आप restaurant में order देते हैं। ठीक वैसे ही client, जैसे browser या mobile app, server को एक request भेजता है।
- 📝 The waiter takes it to the kitchen => The **API** receives the request and routes it
> Waiter आपका order kitchen तक ले जाता है। यही काम API करती है, request को सही जगह पहुँचाती है।
- 👨‍🍳 The kitchen cooks the food => Your **Python code** and database do the work
> Kitchen में खाना बनता है, यानी आपका Python code और database असली काम करते हैं।
- 🍽️ The waiter serves the plate => The API sends back a **JSON response**
> और फिर waiter plate लेकर आता है। API भी result को JSON response बनाकर client को वापस भेज देती है।
:::

::: concept Why FastAPI?
- **Fast to run**: built on Starlette and ASGI, one of the fastest Python frameworks
> FastAPI run होने में बहुत fast है। ये Starlette और A S G I पर बना है, इसलिए Python के सबसे fast frameworks में गिना जाता है।
- **Fast to write**: Python type hints give you validation for free
> और लिखने में भी fast है। आप बस normal Python type hints लिखते हैं, और data validation अपने आप हो जाता है।
- **Auto docs**: Swagger UI and ReDoc generated from your code
> सबसे मज़ेदार बात, documentation आपको अलग से लिखनी नहीं पड़ती। Swagger UI और ReDoc आपके code से अपने आप बन जाते हैं।
- Trusted in production by teams at Microsoft, Uber and Netflix
> इसीलिए Microsoft, Uber और Netflix जैसी companies की teams इसे production में use करती हैं।
:::

::: flow How a request reaches your code
> पहले देखते हैं कि एक request आपके code तक पहुँचती कैसे है।
- Client
> सबसे पहले client request भेजता है।
- Uvicorn (ASGI server)
> इसे Uvicorn receive करता है। Uvicorn एक A S G I server है, जो network वाला काम संभालता है।
- FastAPI app
> Uvicorn वो request आपकी FastAPI app को देता है।
- Your function
> FastAPI URL और method देखकर सही function call करती है। इसे path operation function कहते हैं।
- JSON response
> Function जो भी return करता है, FastAPI उसे JSON में बदलकर client को वापस भेज देती है।
:::

::: code main.py | Your first FastAPI app
```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/")
def read_root():
    return {"message": "Hello, FastAPI!"}


@app.get("/items/{item_id}")
def read_item(item_id: int):
    return {"item_id": item_id}
```
@1 > अब अपनी पहली app लिखते हैं। सबसे पहले FastAPI class import कीजिए।
@3 > फिर उसका एक object बनाइए, app। यही आपकी पूरी application है।
@6 > ये decorator कहता है कि जब कोई slash पर GET request भेजे, तो नीचे वाला function चलाओ।
@7-8 > Function एक normal Python dictionary return करता है, और FastAPI उसे अपने आप JSON में बदल देती है।
@11-12 > दूसरा route थोड़ा smart है। Curly braces में item id एक path parameter है।
@12-13 > और type hint int की वजह से FastAPI उसे number में convert भी करती है और validate भी।
@all > बस इतना ही। सिर्फ तेरह lines में एक working API तैयार है।

::: concept dev vs run
- `fastapi dev main.py`: auto reload, for development only
> fastapi dev सिर्फ development के लिए है, क्योंकि ये हर file change पर server reload करता है।
- `fastapi run main.py`: production mode, no reload, listens on all interfaces
> Production में fastapi run use होता है। ये reload नहीं करता और सभी network interfaces पर listen करता है, जो servers और containers में चाहिए।
- Both start **Uvicorn** under the hood
> दोनों के अंदर Uvicorn ही चलता है।
- Change the port with `--port 9000`
> Port बदलना हो तो dash dash port option दीजिए।
:::

::: concept Free interactive docs
- `/docs`: Swagger UI, try every endpoint from the browser
> अब browser में slash docs खोलिए। ये Swagger UI है, जहाँ से आप हर endpoint को वहीं try कर सकते हैं।
- `/redoc`: clean, readable reference docs
> Slash redoc पर वही docs एक साफ़ reading format में मिलते हैं।
- `/openapi.json`: the OpenAPI schema both are built from
> और ये दोनों बनते हैं slash openapi dot json से। ये OpenAPI schema है, जिससे frontend team typed client code भी generate कर सकती है।
- Docs update automatically when your code changes
> सबसे अच्छी बात, code बदलते ही docs अपने आप update हो जाते हैं। Docs और code कभी out of sync नहीं होते।
:::

::: recap
- An API takes requests and returns responses, usually JSON
> तो जल्दी से recap करते हैं। API request लेती है और response देती है, ज़्यादातर JSON में।
- FastAPI = Starlette (web) + Pydantic (data) + type hints
> FastAPI बना है Starlette, Pydantic और Python type hints से।
- `fastapi dev` for development, `fastapi run` for production
> Development में fastapi dev, और production में fastapi run।
- Type hints convert and validate path parameters
> Type hints से path parameters convert भी होते हैं और validate भी।
- `/docs`, `/redoc` and `/openapi.json` come for free
> और docs आपको बिल्कुल free में मिलते हैं।
:::

::: code profile.py | Project solution walkthrough
```python
from fastapi import FastAPI

app = FastAPI(title="Personal Profile API")
SKILLS = ["Python", "FastAPI", "SQL", "Git"]

@app.get("/")
def home():
    return {"name": "Your Name", "message": "Welcome to my API!"}

@app.get("/skills")
def list_skills():
    return {"count": len(SKILLS), "skills": SKILLS}

@app.get("/skills/{skill_id}")
def get_skill(skill_id: int):
    return {"id": skill_id, "skill": SKILLS[skill_id]}
```
@3 > अब solution देखते हैं। FastAPI को title देने से docs में आपकी API का नाम दिखता है।
@4 > Skills को अभी एक simple list में रखा है। Database हम Level six में लगाएँगे।
@6-8 > Home route आपका नाम और message return करता है।
@10-12 > Skills route पूरी list के साथ उसका count भी देता है।
@14-16 > और skill id वाले route में type hint int है, तो FastAPI number validate करेगी।
@16 > लेकिन ध्यान दीजिए, अगर कोई id ten माँगे, तो list में वो है ही नहीं, और server error आएगा। यही आपका stretch goal है।

::: interview junior
q: What is FastAPI, and why would you choose it over Flask?
- A modern Python framework for APIs, driven by type hints
> FastAPI एक modern Python framework है APIs बनाने के लिए, जो type hints पर चलता है।
- Built-in validation and serialization through Pydantic
> Flask में validation के लिए अलग library लगानी पड़ती है, FastAPI में Pydantic की वजह से ये built-in है।
- Automatic OpenAPI docs and native async on ASGI
> Docs automatic बनते हैं, और async support native है, क्योंकि ये A S G I पर चलता है।
- Flask is still fine for simple sync apps and HTML pages
> Interview में balance दिखाइए। Flask बुरा नहीं है, simple sync apps या HTML pages के लिए अच्छा है। लेकिन modern APIs के लिए FastAPI ज़्यादा productive है।
:::

::: interview junior
q: What is the difference between WSGI and ASGI?
qsay: What is the difference between W S G I and A S G I?
- **WSGI**: synchronous, one request per worker at a time
> W S G I एक synchronous standard है। एक worker एक समय पर सिर्फ एक request handle करता है।
- **ASGI**: asynchronous, one worker serves others while waiting on I/O
> A S G I asynchronous है। जब एक request database या network का wait कर रही हो, तब वही worker दूसरी requests संभाल लेता है।
- ASGI also supports WebSockets and long-lived connections
> और A S G I WebSockets जैसे लंबे connections भी support करता है।
- FastAPI runs on ASGI servers such as Uvicorn
> FastAPI A S G I app है, जो Uvicorn जैसे server पर चलती है।
:::

::: interview mid
q: Where does FastAPI's request validation come from, and what happens when it fails?
- Type hints are turned into Pydantic validation
> FastAPI आपके type hints को Pydantic validation में बदल देती है।
- Input is parsed and converted before your function runs
> Request का data पहले parse और convert होता है, जैसे string forty two से number forty two, और उसके बाद ही आपका function चलता है।
- On failure: **422** with a `detail` list of type, loc and msg
> अगर validation fail हो, तो four twenty two response आता है, detail list के साथ, जिसमें type, loc और msg होते हैं।
- Invalid data never reaches your code
> इसका फायदा ये है कि गलत data आपके business logic तक पहुँचता ही नहीं।
:::

::: interview mid
q: What is the difference between `fastapi dev` and `fastapi run`?
qsay: What is the difference between fastapi dev and fastapi run?
- `dev`: auto reload, binds to 127.0.0.1, local development only
> fastapi dev auto reload करता है और सिर्फ localhost पर चलता है, यानी सिर्फ local development के लिए।
- `run`: no reload, binds to 0.0.0.0, for servers and containers
> fastapi run reload नहीं करता और zero dot zero dot zero dot zero पर listen करता है, जो servers और Docker containers में चाहिए।
- Both start Uvicorn; in production add workers and a reverse proxy
> दोनों Uvicorn ही चलाते हैं। Production में साथ में workers और एक reverse proxy भी रखते हैं, जो हम last level में देखेंगे।
:::

::: interview senior
q: How does FastAPI generate API documentation, and how would you use it in a team?
- Builds an OpenAPI schema from routes, type hints and models
> FastAPI आपके routes, type hints और Pydantic models से एक OpenAPI schema बनाती है।
- Swagger UI and ReDoc render that schema: nothing to sync by hand
> Swagger UI और ReDoc उसी schema को दिखाते हैं, इसलिए docs को manually update नहीं करना पड़ता।
- Teams generate typed clients and contract tests from it
> Team में इस schema से frontend और mobile के लिए typed clients और contract tests generate किए जा सकते हैं।
- Public APIs can hide docs: `FastAPI(docs_url=None, redoc_url=None)`
> और अगर API public है, तो production में docs को बंद या protect कर सकते हैं, docs url को None देकर। Senior level पर ये security awareness ज़रूर दिखाइए।
