::: analogy Production is like opening a restaurant
> Cooking at home and running a restaurant are very different jobs.
- 🍱 Same recipe, every branch => A **Docker image**: same app on every server
> A restaurant chain packs the same recipe for every branch. A Docker image packs your app the same way for every server.
- 👩‍🍳 Several cooks in the kitchen => **Workers** handle requests in parallel
> Several cooks work at once. Workers handle requests in parallel.
- 🧯 Fire and hygiene inspections => **Health checks** and **metrics**
> Inspectors check that everything is safe. Health checks and metrics tell you the app is alive and healthy.
- 📓 The kitchen log => **Structured logs** for every request

::: code Dockerfile | A production Dockerfile
```dockerfile
FROM python:3.13-slim

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1
WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY app ./app

RUN useradd --create-home appuser
USER appuser

EXPOSE 8000
CMD ["fastapi", "run", "app/main.py", "--port", "8000", "--workers", "4", "--proxy-headers"]
```
@1 > Start from the slim official Python image. It's small, and updated with security fixes.
@3-4 > Don't write bytecode files, and print logs immediately, without buffering.
@7-8 > Copy only the requirements first, and install. Docker caches this layer, so rebuilds after code changes take seconds, not minutes.
@10 > Then copy the app code.
@12-13 > Create a normal user, and switch to it. Never run your app as root.
@16 > Start fastapi run with four workers, and trust proxy headers.
@all L> Why copy requirements before the code?
@all > Because your code changes often, and your requirements rarely. Docker only rebuilds the layers after a change.
:::

::: concept Workers, proxies and HTTPS

- 👷 Workers = processes; start near the number of CPU cores
> How many workers? Each worker is a separate process. A good start is about one per CPU core, then measure.
- 🔒 A proxy or load balancer handles HTTPS in front of your app
> In front of your app sits a proxy or load balancer, like Nginx, Traefik or your cloud's. It handles HTTPS certificates.
- 🧭 `--proxy-headers` gives you the real client IP and scheme
> proxy headers lets FastAPI see the real client IP, and whether the request was HTTPS.
- ☸️ On Kubernetes: often 1 worker per container, scale with replicas
> On Kubernetes, many teams run one worker per container, and scale by adding containers instead.
L> So workers don't share memory?
> Right. That's why caches, rate limits and WebSocket messages live in Redis, like in level eleven.

::: code app/core/logging.py | Structured JSON logs
```python
request_id_var: ContextVar[str] = ContextVar("request_id", default="-")


class JsonFormatter(logging.Formatter):
    def format(self, record: logging.LogRecord) -> str:
        entry = {
            "time": self.formatTime(record, "%Y-%m-%dT%H:%M:%S"),
            "level": record.levelname,
            "logger": record.name,
            "message": record.getMessage(),
            "request_id": request_id_var.get(),
        }
        return json.dumps(entry)
```

::: code app/api/health.py | Liveness and readiness
```python
@app.get("/healthz")
async def liveness():
    return {"status": "ok"}


@app.get("/readyz")
async def readiness(session: SessionDep, redis: RedisDep):
    try:
        await session.execute(text("SELECT 1"))
        await redis.ping()
    except Exception:
        log.warning("Readiness check failed")
        return JSONResponse(status_code=503, content={"status": "unavailable"})
    return {"status": "ready"}
```
@1-3 > Liveness answers one question: is the process alive? If not, the platform restarts it. Keep it simple, no database.
@6-9 > Readiness asks: can I serve traffic right now? We check the database and Redis.
@10-12 > If not, five oh three. The load balancer stops sending traffic here, until it's ready again.
@all L> Why not check the database in liveness too?
@all > If the database goes down, every container would be restarted again and again, and that wouldn't fix the database. Restarting can't fix a dependency.

@asynccontextmanager
async def lifespan(app: FastAPI):
    setup_logging(settings.log_level)
    app.state.redis = Redis.from_url(settings.redis_url, decode_responses=True)
    yield
    await app.state.redis.aclose()
    await engine.dispose()


app = FastAPI(title="TaskHub", lifespan=lifespan,
              docs_url=None if settings.env == "prod" else "/docs")
app.add_middleware(RequestContextMiddleware)
app.add_exception_handler(Exception, unhandled)
app.include_router(health_router)
app.include_router(api_router, prefix="/api/v1")
Instrumentator().instrument(app).expose(app, include_in_schema=False)
