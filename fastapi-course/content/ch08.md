::: code app/core/security.py | Hashing passwords
```python
from pwdlib import PasswordHash

password_hash = PasswordHash.recommended()


def hash_password(password: str) -> str:
    return password_hash.hash(password)


def verify_password(password: str, hashed: str) -> bool:
    return password_hash.verify(password, hashed)
```
```output
hash_password("secret123")
-> "$argon2id$v=19$m=65536,t=3,p=4$Xq...$Jd..."   (different every time)
```
@1-3 > recommended gives you Argon2, a modern, deliberately slow hashing algorithm.
@6-7 > When a user signs up, we store only the hash, never the password itself.
@10-11 > At login, verify checks a password against the stored hash.
@out > The hash includes a random salt, so the same password produces a different hash every time.
@out L> Why slow on purpose?
@out > So that if your database leaks, attackers can only try a handful of guesses per second, instead of billions.
:::

::: mistake Comparing plain-text passwords
```python
user = await users.get_by_email(form.username)
if user is None or user.password != form.password:
    raise HTTPException(status_code=401)
```
```python
user = await users.get_by_email(form.username)
if user is None or not verify_password(form.password, user.hashed_password):
    raise HTTPException(status_code=401)
```
@wrong > If you can compare passwords like this, it means you stored them in plain text.
L> And one database leak exposes every password, including ones people reuse on other sites.
> Exactly. It happens to real companies every year.
@right > Store only hashes, and verify with the hashing library.
:::

::: code app/core/security.py | Creating JWT access tokens
```python
from datetime import datetime, timedelta, timezone

import jwt

ALGORITHM = "HS256"


def create_access_token(subject: str, minutes: int = 30) -> str:
    expire = datetime.now(timezone.utc) + timedelta(minutes=minutes)
    payload = {"sub": subject, "exp": expire}
    return jwt.encode(payload, settings.secret_key, algorithm=ALGORITHM)
```
@3 > Import PyJWT.
@8-9 > The token expires after thirty minutes. Always use timezone aware UTC times.
@10 > The payload holds sub, the subject, which is the user's id, and exp, the expiry.
@11 > And we sign it with our secret key from settings.
:::

::: concept What's inside a JWT?
visual: lock
- 🧾 Three parts: `header.payload.signature`
> A JWT has three parts, separated by dots: header, payload and signature.
- 👀 The payload is only **encoded**, not encrypted
> The payload is only base64 encoded, not encrypted. Anyone can read it.
- ✍️ The signature proves the server created it
> The signature proves our server created it, and that nobody changed it.
- 🚫 Never put secrets or passwords in the payload
> So never put secrets or personal data in the payload.
L> Wait, anyone can read my token?
> Yes. Paste one into any JWT decoder. That's fine, because they can't change it without breaking the signature.
:::

::: code app/api/v1/auth.py | The login endpoint
```python
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/api/v1/auth/token")


@router.post("/token")
async def login(form: Annotated[OAuth2PasswordRequestForm, Depends()], users: UserRepoDep):
    user = await users.get_by_email(form.username)
    if user is None or not verify_password(form.password, user.hashed_password):
        raise HTTPException(
            status_code=401,
            detail="Incorrect email or password",
            headers={"WWW-Authenticate": "Bearer"},
        )
    token = create_access_token(subject=str(user.id))
    return {"access_token": token, "token_type": "bearer"}
```
@1 > OAuth2 password bearer tells FastAPI, and the docs, where clients get tokens.
@4-5 > The login form follows the OAuth2 standard: a username field and a password field. We use the email as the username.
@7-12 > Wrong email or wrong password gives the same four oh one, with the same message.
@7 L> Why the same message for both?
@7 > So attackers can't use the login form to find out which emails are registered.
@13-14 > Otherwise, we return the token in the standard OAuth2 shape.

::: code app/api/deps.py | get_current_user
```python
async def get_current_user(token: Annotated[str, Depends(oauth2_scheme)], users: UserRepoDep) -> User:
    credentials_error = HTTPException(
        status_code=401,
        detail="Could not validate credentials",
        headers={"WWW-Authenticate": "Bearer"},
    )
    try:
        payload = jwt.decode(token, settings.secret_key, algorithms=[ALGORITHM])
    except jwt.InvalidTokenError:
        raise credentials_error
    user = await users.get(int(payload["sub"]))
    if user is None or not user.is_active:
        raise credentials_error
    return user


CurrentUser = Annotated[User, Depends(get_current_user)]
```
@1 > oauth2 scheme reads the token from the Authorization header.
@7-10 > decode checks the signature and the expiry. A forged or expired token raises InvalidTokenError, and we answer four oh one.
@8 > Always pass the algorithms list. It stops attackers from switching the algorithm.
@11-13 > Then we load the user, and reject unknown or deactivated accounts.
@17 > And CurrentUser becomes the one line any endpoint needs to require login.
:::

::: code app/api/deps.py | Roles and ownership
```python
def require_role(role: str):
    def checker(user: CurrentUser) -> User:
        if user.role != role:
            raise HTTPException(status_code=403, detail="Not enough permissions")
        return user
    return checker


@router.get("/tasks/{task_id}", response_model=TaskRead)
async def get_task(task_id: int, user: CurrentUser, tasks: TaskRepoDep):
    task = await tasks.get(task_id)
    if task is None or task.owner_id != user.id:
        raise HTTPException(status_code=404, detail="Task not found")
    return task
```
@1-6 > require role is a dependency factory. It returns a checker for whichever role you need, and answers four oh three.
@9-14 > Ownership is just as important. Users must only see their own tasks.
@12-13 > If the task belongs to someone else, we answer four oh four, not four oh three.
@12 L> Why hide it instead of saying forbidden?
@12 > A four oh three would confirm that task twelve exists. A four oh four reveals nothing. Many real data leaks come from missing ownership checks like this one.
