::: code db.py | Async engine and a session per request
```python
from typing import Annotated, AsyncIterator

from fastapi import Depends
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker, create_async_engine

DATABASE_URL = "sqlite+aiosqlite:///./taskhub.db"
engine = create_async_engine(DATABASE_URL)
SessionLocal = async_sessionmaker(engine, expire_on_commit=False)


async def get_session() -> AsyncIterator[AsyncSession]:
    async with SessionLocal() as session:
        yield session


SessionDep = Annotated[AsyncSession, Depends(get_session)]
```
@6-7 > The engine manages connections. The URL uses aiosqlite, the async driver.
@8 > SessionLocal is a factory that creates sessions. expire on commit false matters with async: without it, reading an object after commit triggers an error.
@11-13 > And here's level five's yield dependency again. Every request gets its own session, closed automatically when the request ends.
@16 > SessionDep is the alias every endpoint will use.

::: code main.py | Create and list tasks
```python
@app.post("/tasks", response_model=TaskRead, status_code=201)
async def create_task(data: TaskCreate, session: SessionDep):
    task = Task(**data.model_dump())
    session.add(task)
    await session.commit()
    await session.refresh(task)
    return task


@app.get("/tasks", response_model=list[TaskRead])
async def list_tasks(session: SessionDep, done: bool | None = None):
    stmt = select(Task).order_by(Task.id)
    if done is not None:
        stmt = stmt.where(Task.done == done)
    result = await session.scalars(stmt)
    return result.all()
```
@2 > The endpoints are now async def, because database calls are awaited.
@3-4 > Build a Task from the validated data and add it to the session.
@5-6 > Commit saves it, and refresh loads the id and created at that the database generated.
@12-14 > For the list, build a select statement, and add the done filter only if the client sent it.
@15-16 > session dot scalars returns Task objects. This is the SQLAlchemy two query style.
:::

async def get_task_or_404(task_id: int, session: SessionDep) -> Task:

    if task is None:
        raise HTTPException(status_code=404, detail="Task not found")

TaskDep = Annotated[Task, Depends(get_task_or_404)]
@app.patch("/tasks/{task_id}", response_model=TaskRead)
async def update_task(task: TaskDep, changes: TaskUpdate, session: SessionDep):
    for field, value in changes.model_dump(exclude_unset=True).items():

    await session.commit()

::: code models.py | Relationships and the N+1 problem
```python
class Project(Base):
    __tablename__ = "projects"

    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(80))
    tasks: Mapped[list["Task"]] = relationship(back_populates="project")


# 1 query for projects + 1 query PER project = N+1
# fix: load all their tasks in one extra query
stmt = select(Project).options(selectinload(Project.tasks))
projects = (await session.scalars(stmt)).all()
```
@1-6 > Now a Project model with many tasks. relationship creates the one to many link.
@9 > Here's the trap. List fifty projects, load each one's tasks separately, and you run fifty one queries. That's the N plus one problem.
@10-12 > The fix is selectinload: all the tasks arrive in one extra query, so two queries in total. I counted them in this course's tests.
@11 L> Would I even notice the slow version?
@11 > Not with ten rows on your laptop. You'd notice in production, with real traffic. That's why it's an interview favourite.

::: code main.py | Project solution: search, filter and limit
```python
@app.get("/tasks", response_model=list[TaskRead])
async def list_tasks(
    session: SessionDep,
    done: bool | None = None,
    q: Annotated[str | None, Query(min_length=2)] = None,
    limit: Annotated[int, Query(ge=1, le=100)] = 20,
):
    stmt = select(Task).order_by(Task.id.desc()).limit(limit)
    if done is not None:
        stmt = stmt.where(Task.done == done)
    if q:
        stmt = stmt.where(Task.title.ilike(f"%{q}%"))
    return (await session.scalars(stmt)).all()
```
@4-6 > Here's my solution. The filters reuse level two's validation: q needs two characters, and limit is capped at a hundred.
@8 > Newest first, and the limit goes into the SQL query itself, so the database never returns extra rows.
@11-12 > For search, ilike does a case insensitive match. The percent signs mean anywhere in the title.
:::

::: interview mid
q: Sync vs async database access in FastAPI: what changes, and what must you avoid?
- Async: `async def` + async driver (asyncpg, aiosqlite) + `await`
> With async, I use async def endpoints, an async driver like asyncpg, and await every call.
- Sync: plain `def` endpoints run in a threadpool
> With sync, plain def endpoints run in a threadpool with a normal session.
- Never call a blocking driver inside `async def`
> The big mistake is calling a blocking driver inside async def. It freezes the event loop and slows down every request.
- Async shines with many concurrent I/O-bound requests
> Both work, but async shines when you have lots of concurrent requests waiting on I/O.
M> Calling out that mistake is what separates a mid level answer from a junior one.
:::
