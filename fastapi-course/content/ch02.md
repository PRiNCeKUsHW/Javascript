::: analogy Path vs query: an address vs shopping filters
> इन दोनों का फ़र्क एक आसान example से समझते हैं।
- 📍 A house address: Street 5, House 42 => **Path params** identify one thing: `/users/42`
> किसी का घर ढूँढना हो तो पूरा address चाहिए, street five, house forty two। Path parameter भी ऐसे ही एक खास चीज़ को identify करता है, जैसे user forty two।
- 🛒 Shopping filters: under ₹500, colour red => **Query params** filter or sort: `/products?max_price=500`
> Online shopping में आप filters लगाते हैं, जैसे price five hundred से कम, colour red। Query parameters यही काम करते हैं, filter, sort और search।
- 🏠 No address, no delivery => Path params are always required
> Address के बिना delivery नहीं हो सकती, इसलिए path parameter हमेशा required होता है।
- 🎛️ Filters are optional => Query params can have defaults
> लेकिन filters optional होते हैं, इसलिए query parameters को default value दे सकते हैं।
:::

::: code users.py | Path parameters and route order
```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/users/me")
def read_current_user():
    return {"user": "the current user"}


@app.get("/users/{user_id}")
def read_user(user_id: int):
    return {"user_id": user_id}
```
@11-13 > ये path parameter है। user id URL से आता है, और int type hint की वजह से FastAPI उसे number बना देती है।
@6-8 > अब एक fixed path भी है, users slash me, जो logged in user के लिए है।
@6 > ध्यान दीजिए, ये route ऊपर लिखा है। FastAPI routes को ऊपर से नीचे check करती है, और जो पहला match होता है वही चलता है।
@11 > अगर users slash user id ऊपर होता, तो me वाली request उसी में चली जाती, और me को number बनाने में four twenty two error आता।
@all > इसलिए rule याद रखिए, fixed paths पहले, और parameter वाले paths बाद में।
:::

::: code movies.py | Enum: only allow fixed choices
```python
from enum import Enum

from fastapi import FastAPI

app = FastAPI()


class Genre(str, Enum):
    action = "action"
    comedy = "comedy"
    drama = "drama"


@app.get("/movies/genre/{genre}")
def movies_by_genre(genre: Genre):
    if genre is Genre.comedy:
        return {"genre": genre, "tip": "Get the popcorn ready!"}
    return {"genre": genre}
```
@8-11 > जब value कुछ fixed options में से ही होनी चाहिए, तो Enum use कीजिए। यहाँ सिर्फ तीन genres allowed हैं।
@14-15 > Path parameter का type Genre रख दिया। अब horror भेजेंगे तो FastAPI खुद four twenty two देगी।
@16-17 > Function के अंदर आप Enum members से compare कर सकते हैं।
@all > और bonus ये है कि slash docs में ये तीनों options एक dropdown में दिखते हैं।

::: code movies.py | Query parameters with defaults
```python
from fastapi import FastAPI

app = FastAPI()
MOVIES = [{"title": "Inception", "year": 2010}, {"title": "Dangal", "year": 2016}]


@app.get("/movies")
def list_movies(
    skip: int = 0,
    limit: int = 10,
    year: int | None = None,
):
    results = [m for m in MOVIES if year is None or m["year"] == year]
    return results[skip : skip + limit]
```
@7-8 > अब query parameters देखते हैं। जो parameter path में नहीं है, वो अपने आप query parameter बन जाता है।
@9-10 > skip और limit को default values दी हैं, तो ये optional हैं। ये pagination के लिए हैं।
@11 > year का default None है, यानी filter लगाना है या नहीं, ये user की मर्ज़ी।
@13-14 > अंदर year से filter किया, और skip और limit से list का हिस्सा काटा।
:::

::: concept Query parameter rules
- No default value → **required**: `q: str`
> Query parameter को default नहीं दिया, तो वो required बन जाता है।
- `= None` → optional: `year: int | None = None`
> None default देने से वो optional बन जाता है।
- `bool` understands `true`, `1`, `yes`, `on`
> bool type हो, तो true, one, yes और on, सब True माने जाते हैं।
- Many values: a `list[str]` type with `Query()` → `?tag=a&tag=b`
> और एक ही parameter कई बार भेजना हो, जैसे कई tags, तो list type और Query use कीजिए।
:::

::: code movies.py | Validation with Annotated, Path and Query
```python
from typing import Annotated

from fastapi import FastAPI, Path, Query

app = FastAPI()


@app.get("/movies/{movie_id}")
def get_movie(
    movie_id: Annotated[int, Path(ge=1, description="Movie ID")],
    q: Annotated[str | None, Query(min_length=3, max_length=50)] = None,
):
    return {"movie_id": movie_id, "q": q}
```
@1-3 > अब असली validation। इसके लिए Annotated, Path और Query import कीजिए।
@10 > Annotated में पहले type आता है, फिर rules। यहाँ ge one का मतलब है greater than or equal to one। Zero या negative id नहीं चलेगी।
@11 > q एक optional search text है, जिसकी length तीन से पचास के बीच होनी चाहिए।
@all > Rules आपके function signature में ही लिखे हैं। ना if conditions, ना manual errors, और ये सब docs में भी दिखता है।

::: recap
- Path params identify a resource and are always required
> Recap। Path parameters किसी एक resource को identify करते हैं, और हमेशा required होते हैं।
- Declare fixed paths like `/users/me` before `/users/{id}`
> Fixed paths हमेशा parameter वाले paths से पहले लिखिए।
- Use `Enum` when only a few values are allowed
> जब कुछ ही values allowed हों, तो Enum।
- Query params filter, sort and paginate; give them defaults
> Query parameters filter, sort और pagination के लिए हैं, और उन्हें defaults दीजिए।
- `Annotated[..., Path(...)]` and `Query(...)` add validation rules
> और Annotated के साथ Path और Query से validation rules लगाइए।
:::

::: practice
q: `GET /users/me` keeps returning 422 in your app. What is the most likely bug?
qsay: सवाल नंबर एक. आपकी app में users slash me हमेशा four twenty two दे रहा है। सबसे likely bug क्या है?

- `/users/{user_id}` is declared **before** `/users/me`

- "me" is matched as `user_id` and fails the int check
> तो me को user id समझा गया, और int में convert नहीं हुआ, इसलिए four twenty two।

> Fix simple है, users slash me वाला route ऊपर ले आइए।

::: code movies.py | Project solution: the search endpoint
```python
@app.get("/movies")
def list_movies(
    genre: Genre | None = None,
    year: int | None = None,
    min_rating: Annotated[float, Query(ge=0, le=10)] = 0,
    skip: Annotated[int, Query(ge=0)] = 0,
    limit: Annotated[int, Query(ge=1, le=50)] = 10,
):
    results = [
        m for m in MOVIES
        if (genre is None or m["genre"] == genre)
        and (year is None or m["year"] == year)
        and m["rating"] >= min_rating
    ]
    return {"total": len(results), "items": results[skip : skip + limit]}
```
@3-4 > Genre और year optional filters हैं, default None।
@5 > Minimum rating पर zero से ten का rule।
@6-7 > skip कभी negative नहीं, और limit एक से fifty के बीच।
@9-14 > फिर list comprehension से सारे filters एक साथ लगाए।
@15 > और response में total count भी भेजा, ताकि frontend को पता हो कि कितने pages हैं। Real APIs में ये बहुत common pattern है।

::: interview junior
q: What is the difference between a path parameter and a query parameter? When do you use each?
- Path param identifies **one resource**: `/users/42`
> Path parameter एक खास resource को identify करता है, जैसे user forty two।
- Query param **filters, sorts, searches or paginates**: `/users?role=admin`
> Query parameter उस list को filter, sort, search या paginate करता है।
- Path params are required; query params are usually optional
> Path parameters required होते हैं, और query parameters ज़्यादातर optional, defaults के साथ।
- Rule of thumb: if removing it changes **what** you fetch, it's a path param
> एक आसान rule बताइए: अगर उसे हटाने से resource ही बदल जाए, तो वो path parameter है, वरना query।
:::

::: interview junior
q: Why does route order matter in FastAPI? Give an example.
- Routes are matched **top to bottom**, the first match wins
> FastAPI routes को ऊपर से नीचे match करती है, और जो पहला match हो, वही चलता है।
- `/users/{id}` declared first would capture `/users/me`
> अगर users slash id पहले लिखा हो, तो users slash me भी उसी में चला जाएगा।
- Declare fixed paths before parameterised ones
> इसलिए fixed paths पहले, parameter वाले बाद में।
:::

::: interview mid
q: How do you validate query and path parameters in FastAPI, and why is `Annotated` recommended?
qsay: How do you validate query and path parameters in FastAPI, and why is Annotated recommended?
- `Path()` and `Query()` add rules: `ge`, `le`, `min_length`, `pattern`
> Path और Query से rules लगते हैं, जैसे ge, le, min length, max length और regex pattern।
- `Annotated[type, Query(...)]` keeps the real default as a normal Python default
> Annotated में type और rules साथ रहते हैं, और default value normal Python default की तरह लिखी जाती है।
- The same function works when called directly, and the metadata is reusable
> इससे function को direct call करना भी आसान है, और वही Annotated type कई endpoints में reuse हो सकता है।
- Failures return 422 with the exact location of the problem
> Validation fail हो तो four twenty two, और loc में साफ़ लिखा होता है कि गलती कहाँ है।

::: interview mid
q: How would you design pagination parameters for a list endpoint?
- `skip`/`offset` ≥ 0 and `limit` with a **maximum** (for example 100)
> skip या offset कभी negative नहीं, और limit पर एक maximum ज़रूर लगाइए, जैसे hundred।
- The max limit protects the database and response size
> Maximum limit इसलिए, ताकि कोई एक request में लाखों rows माँगकर database को slow ना कर दे।
- Return `total` or a `next` link so clients know when to stop
> Response में total count या next page का link दीजिए, ताकि client को पता हो कब रुकना है।
- For huge or fast-changing tables, use cursor pagination (Level 11)
> और बहुत बड़ी tables के लिए offset slow हो जाता है, वहाँ cursor pagination बेहतर है, जो हम Level eleven में देखेंगे।
:::

::: interview senior
q: How would you evolve query parameters without breaking existing API clients?
- Only **add** optional params with safe defaults
> नए query parameters हमेशा optional और safe default के साथ जोड़िए, ताकि पुराने clients ना टूटें।
- Rename with `Query(alias="old_name")` or keep both for a while
> Parameter का नाम बदलना हो, तो alias से पुराना नाम कुछ समय तक support कीजिए।
- Mark old ones `Query(deprecated=True)` so docs warn clients
> पुराने parameters को deprecated true mark कीजिए, ताकि docs में warning दिखे।
- Breaking change? Ship it as a new version, like `/api/v2`
> और अगर breaking change ज़रूरी है, तो उसे नए version में लाइए, जैसे api slash v two। Senior level पर backward compatibility की ये सोच बहुत important है।
:::
